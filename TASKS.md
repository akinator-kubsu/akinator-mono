
**Общие сквозные требования (действуют на всех этапах):**

*   **GitLab:** Все изменения сохраняются только на GitLab лаборатории КубГУ. Реализация любого требования – больше одного коммита. У любого участника команды – больше одного коммита.
*   **Развертывание:** Все сервисы должны быть подняты на ресурсах лаборатории КубГУ.
*   **Автотесты:** На HTTP сервисы прописаны автотесты, проведены, отчеты сохранены.
*   **Swagger:** На каждый HTTP сервис подготовлен Swagger и доступен на ресурсах лаборатории КубГУ.

---

**Предварительный этап (необходим перед началом, вне оценок):**

1.  **P0.1: Выбор предметной области и сбор данных:**
    *   Определить конкретную область (например, "Персонажи Marvel Comics").
    *   Собрать не менее 150 объектов (персонажей) для этой области.
    *   Продумать не менее 8 общих вопросов и начать формировать специфичные вопросы для различения похожих объектов.
2.  **P0.2: Настройка окружения:**
    *   Установить SWI-Prolog, .NET SDK (включая F#), выбранную СУБД (например, PostgreSQL).
    *   Настроить IDE для разработки на Prolog, C#, F#.
3.  **P0.3: Создание репозитория:**
    *   Создать проект на GitLab лаборатории КубГУ.

**План для Оценки "Удовлетворительно" (3)**

*Предполагается выполнение "плюсовых" требований как основы для "удовлетворительно".*

**I. Логическая часть (Prolog):**

1.  **Задача 1 (FR1.1 - Базовый Prolog Акинатор):**
    *   **Цель:** Создать ядро игры на Prolog.
    *   **Реализация:**
        *   Разработать структуру фактов Prolog для объектов (150+) и вопросов (8+).
        *   Реализовать предикаты для:
            *   Задавания вопросов пользователю в терминале Prolog.
            *   Обработки ответов.
            *   Поиска подходящего объекта (угадывания).
            *   **Ранней выдачи ответа:** если после N вопросов остался 1 кандидат, выдать его.
            *   **Разных вопросов для разных объектов:** логика ветвления для специфичных вопросов после общих.
            *   Добавления нового объекта (имя, ответы на заданные вопросы), если объект не угадан (через `assertz`).
    *   **Коммиты:** Минимум 2-3 (начальная структура, логика игры, добавление объекта и спец. возможности).

2.  **Задача 2 (FR1.2 - HTTP Сервис для Prolog-логики – `AkinatorLogicService`):**
    *   **Цель:** Предоставить HTTP API для взаимодействия с Prolog-Акинатором.
    *   **Реализация:**
        *   Использовать встроенный HTTP-сервер SWI-Prolog.
        *   **Endpoint 1 (GET/POST):** `/game/next_question` или `/game/answer` - принимает текущее состояние/ответ, возвращает следующий вопрос, или угаданный объект, или сообщение об отсутствии объекта.
        *   **Endpoint 2 (POST):** `/game/add_object` - принимает имя нового объекта и последовательность ответов, добавляет его в Prolog-базу.
        *   **Swagger:** Подготовить OpenAPI спецификацию.
        *   **Автотесты:** Написать (например, curl скрипты или Postman-коллекция с newman).
        *   **Развертывание:** На ресурсах лаборатории.
    *   **Коммиты:** Минимум 2-3 (настройка сервера, каждый эндпоинт, Swagger, тесты).

**II. Императивная часть (ASP.NET и БД):**

1.  **Задача 3 (FR2.1 - База данных):**
    *   **Цель:** Создать БД для хранения пользовательских данных и сессий.
    *   **Реализация:**
        *   Спроектировать схему БД:
            *   `Users` (UserId, Username, PasswordHash и т.д. для **аутентификации**).
            *   `GameSessions` (SessionId, UserId, StartTime, EndTime, GuessedObjectId, AddedObjectName).
            *   `SessionAnswers` (SessionAnswerId, SessionId, QuestionText, UserAnswer).
        *   Создать БД на сервере лаборатории.
    *   **Коммиты:** Минимум 2 (схема, скрипты создания).

2.  **Задача 4 (FR2.2 - REST сервис ASP.NET – `AkinatorApiService`):**
    *   **Цель:** Сервис для управления пользователями и сеансами игры.
    *   **Реализация:**
        *   Создать ASP.NET Core Web API проект.
        *   Настроить EF Core для работы с БД из Задачи 3.
        *   **Endpoint для пользователей (POST):** `/api/users/register` (добавление пользователя).
        *   **Endpoint для аутентификации (POST):** `/api/users/login` (для последующей авторизации).
        *   **Endpoints для сессий (POST, PUT):** `/api/sessions` (начать сессию), `/api/sessions/{id}` (обновить/завершить сессию, сохранить загаданного/добавленного персонажа, ответы).
        *   **Swagger:** Подготовить OpenAPI спецификацию.
        *   **Автотесты:** Написать (xUnit/NUnit с TestServer).
        *   **Развертывание:** На ресурсах лаборатории.
    *   **Коммиты:** Минимум 2-3 (настройка проекта, каждый тип эндпоинтов, Swagger, тесты).

**III. Функциональная часть (F#):**

1.  **Задача 5 (FR3.1 - F# запросы к БД):**
    *   **Цель:** Реализовать аналитические запросы на F#.
    *   **Реализация:**
        *   Создать F# проект (библиотеку классов).
        *   Настроить доступ к БД из Задачи 3 (например, через EF Core или SQLProvider).
        *   **Запрос 1:** "Топ-N самых часто угадываемых персонажей" (по `GameSessions.GuessedObjectId`).
        *   **Запрос 2:** "Среднее количество вопросов до угадывания персонажа по всем сессиям".
        *   Реализовать запросы в функциональном стиле.
    *   **Коммиты:** Минимум 2 (настройка, каждый запрос).

2.  **Задача 6 (FR3.2 - Внедрение F# модуля в `AkinatorApiService`):**
    *   **Цель:** Предоставить результаты F# запросов через API.
    *   **Реализация:**
        *   Интегрировать F# библиотеку из Задачи 5 в `AkinatorApiService`.
        *   Добавить новые REST-ручки в `AkinatorApiService` (например, `/api/statistics/top-guessed`, `/api/statistics/avg-questions`), которые вызывают F# функции.
        *   Обновить Swagger для `AkinatorApiService`.
        *   Обновить автотесты для `AkinatorApiService`.
    *   **Коммиты:** Минимум 2 (интеграция, ручки, док/тесты).

**IV. Интеграционная часть (Клиент):**

1.  **Задача 7 (FR4.2 - Клиентское приложение с HTTP сервисами):**
    *   **Цель:** Создать пользовательский интерфейс для игры и отображения статистики.
    *   **Реализация:**
        *   Выбрать технологию (Web: Blazor/ASP.NET MVC; .NET Desktop: WPF).
        *   **Обязательная авторизация пользователя:** UI для входа (использует `/api/users/login` из `AkinatorApiService`), передача токена/сессии в последующих запросах.
        *   **Игровой процесс:**
            *   Взаимодействие с `AkinatorLogicService` (Задачи 1, 2) для получения вопросов, отправки ответов, получения результата, добавления нового персонажа.
            *   Сохранение информации о сеансе игры через `AkinatorApiService` (Задача 4).
        *   **Отображение статистики:** Данные для статистики должны быть получены **только** через вызов REST-ручек `AkinatorApiService` (Задача 6), реализующих запросы из FR3.1.
    *   **Коммиты:** Множество коммитов, отражающих разработку UI, интеграцию с каждым сервисом, авторизацию, отображение статистики.
